# 阅星人学生习作工作台

把“上传手写原稿 → 整理文字 → 核对正文与摘录 → 下载家长分享长图”做成可反复使用的网页工具。支持电脑和手机，使用自己的 AI API，也可以手动粘贴文字。最终交付为 **PNG 与 JPG 图片**。

这是 React + Vite 静态项目，适合部署到 GitHub Pages。无需数据库、服务器账号或包含 API 密钥的环境变量。

## 数据存放在哪里

- 网页部署在网上；学生照片、正文、疑难字与确认状态保存在当前浏览器的 **IndexedDB** 中，工作台不会把它们提交到 GitHub 仓库。
- 每个设备、浏览器和网站地址的本机数据独立。另一台电脑或手机打开同一网址，可以使用工具，但不会自动看到原设备的作业；本版没有账号登录和跨设备同步。
- API 密钥只保留在当前页面内存中，不写入 IndexedDB、localStorage、代码仓库或部署配置。刷新、关闭后需要重新输入。
- 只有主动点击 **AI 识别**，原稿图片和识别指令才会发送到你配置的 AI 服务。手动整理、确认和图片导出在浏览器本机完成。
- 清理浏览器网站数据、使用无痕模式、卸载浏览器或更换设备，可能导致草稿丢失。**本机数据丢失后，工作台无法恢复。** 重要原稿请另行保存，完成后及时下载成品。

## 使用流程

1. **建立同学的作品。** 每位同学使用独立作品，填写能确认的姓名、题目和日期。缺失的信息留空，不补造。不要把不同孩子的照片放进同一作品。
2. **上传并排好原稿。** 添加这位同学的 JPG、PNG 或 WebP 照片，按作文顺序调整页序。先检查是否缺页、错放或顺序不明。
3. **识别或粘贴文字。** 填好 API 设置后主动运行 AI 识别；也可粘贴已有转写稿并对照照片核查。AI 只做最小校订，保留孩子的原意和口吻。AI 可能识别错误，仍须人工看原稿核对。
4. **处理疑难字。** 逐项核对识别提出的问题，修正文中 `【待确认】` 标记，并在核实后清空对应待核对问题。未解决的疑难字会阻止确认和导出。
5. **核对完整正文。** 检查题目、姓名、日期、段落、书信格式和原稿是否一致，然后明确确认正文。
6. **单独核对摘录。** 需要摘录时，展示并确认拟用的完整原句；它必须逐字出自最终正文，标点也保持一致。不需要时关闭摘录，成图省略摘录区。确认正文不会自动确认摘录。
7. **生成、检查并下载。** 正文与必要的摘录确认后，才能生成长图。检查全文、原稿页序、照片清晰度及预览中是否有裁切，下载 JPG 供分享、PNG 供高清保存。
8. **清理草稿。** 完成下载并确认文件可打开后，可在工作台删除不再需要的作品或清空草稿。删除后的本机草稿无法恢复；若要彻底移除该网站保存的数据，也可在浏览器的网站数据设置中清除本站数据。

正文重新识别或修改后，需要重新确认。修改摘录或开关摘录后，需要重新确认相应摘录。更换、移动、重排原稿会撤销相关确认，避免文字和原稿对应错误；修改题目、副标题、姓名、日期也会要求重新核对。

仅需文字时，完成文字整理后直接复制保存即可，不必进入摘录确认和出图流程。粘贴文字可以用于整理，但制作包含手写原稿的长图仍需上传原稿照片。

## 照片上传

超大照片会在浏览器内自动等比缩小，并以高质量 JPG 继续处理，不再因超过 4000 万像素而要求手动缩图。最长边控制在 4096 px，保留整页比例，不裁切；普通尺寸照片保留原文件内容。处理不会改动你电脑或手机里的原文件。单个输入文件上限为 100 MB；浏览器仍需能够正常解码照片。

## 接入自己的 AI API

在网页的 API 设置中选择接口类型，填写 API 地址、支持图片输入的模型名称和密钥。不要把密钥写进项目文件，也不要提交到 GitHub。

| 接口类型 | 默认 API 地址 | 要求 |
| --- | --- | --- |
| OpenAI 兼容 | `https://api.openai.com/v1` | 兼容 Chat Completions、图片输入和 JSON 输出 |
| Gemini | `https://generativelanguage.googleapis.com/v1beta` | 支持图片输入及 JSON 输出的 Gemini 模型 |
| DeepSeek | `https://api.deepseek.com` | 默认 `deepseek-flash`，支持原稿照片输入及 JSON 输出 |

选择 DeepSeek 后自动填好地址及 `deepseek-flash` 模型，填写自己的 DeepSeek 密钥即可。按 [DeepSeek 官方图像理解文档](https://api-docs.deepseek.com/zh-cn/guides/vision/) 接入；`deepseek-v4-pro` 不支持图片，旧的 `deepseek-chat` / `deepseek-reasoner` 也不适用于本工作台的照片识别。切换服务商时会清空当前密钥输入，避免误用其他服务的密钥。

可以改成兼容上述协议的自有服务地址。请使用**多模态模型**；仅支持文字的模型不能读取手写照片。模型名称和可用额度以服务商账户为准。

浏览器直接调用外部 API，服务商必须允许当前网页来源的跨域请求（**CORS**）。如果配置无误仍提示连接失败，请检查服务商的 CORS、网络和模型权限。GitHub Pages 只能托管静态文件，不能替你运行代理或绕过跨域限制。

建议使用额度受限、权限受限的专用密钥；如需把上游密钥保存在服务器，或服务商不支持网页跨域调用，可配置你自己控制的兼容代理。代理应自行做好访问鉴权、来源限制和额度控制。网页中的密钥即使只在内存里，仍可被本机浏览器及其扩展读取。

本次开发未使用真实学生资料，也未填入真实 API 密钥；已对适配与错误处理进行自动化测试，**实际服务商的识别效果、账户权限和跨域连接仍需使用自己的密钥验证**。

## 图片导出与长篇限制

成图宽度为 1440 px，高度随内容增长；使用本地随项目提供的 MiSans 和阅星人品牌 Logo。顺序为题目与署名信息、可选原句摘录、文字整理稿、逐页手写原稿和品牌落款。原稿保持比例与页序。

导出使用浏览器 Canvas。超长正文或过多原稿可能超过浏览器的画布尺寸或内存上限，手机更容易受限制。遇到超长提示时，请把作品按合理内容拆成几篇后分别制作；不要删掉正文或把多页原稿缩成难读的缩略图。下载的 PNG/JPG 是本工作流的终点，工作台不会自动发布到公众号或发送给家长。

## 本机开发

建议 Node.js 22。进入项目目录运行：

```sh
npm ci
npm run dev
```

运行检查、构建和本机预览：

```sh
npm test
npm run build
npm run preview
```

构建结果在 `dist/`。Vite 已设置相对资源路径 `base: './'`，可用于 GitHub Pages 的仓库子路径。不需要 `.env` 中的 API 密钥，也不需要创建数据库。

## 部署到 GitHub Pages

目标仓库为 `HanRoots/yuexingren-writing-workbench`。仓库创建和 GitHub Pages 首次启用需在 GitHub 完成；此 README 不表示站点已经部署成功。

1. 将项目代码与 `package-lock.json` 提交到该仓库的 `main` 分支。不要提交学生照片、导出的学生成图、正文备份或密钥。
2. 打开仓库 **Settings → Pages**，将 **Build and deployment → Source** 设为 **GitHub Actions**。
3. 推送 `main`，或在 **Actions → Deploy GitHub Pages → Run workflow** 手动触发部署。
4. 工作流使用 Node.js 22 执行 `npm ci`、`npm run build`，上传 `dist/`，再由官方 Pages Action 部署。等待构建和部署均成功后，使用工作流返回的网址访问。

按默认 GitHub Pages 地址规则，成功部署后的地址通常为：

```text
https://hanroots.github.io/yuexingren-writing-workbench/
```

公开 GitHub Pages 仓库中的内容是前端代码、项目配置和用于展示的品牌素材，不包含学生作业数据库。API 密钥由每次使用者在网页中输入，无需设置 GitHub Actions Secret。品牌素材的使用范围请沿用阅星人已有授权。

之后更新代码并推送 `main` 即可重新部署。更换站点域名、浏览器或设备会切换本机数据存放位置；迁移前请先保存所需原稿与成品。
